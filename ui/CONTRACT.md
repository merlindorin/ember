# ui contract

The types the pipeline stages share. ui-developer-lead owns them; ask before changing one, and add fields freely when you only add.

| Stage | Reads | Writes | Entry point |
|---|---|---|---|
| css (dev-2) | `*dom.Node` (tag, id, classes, attrs, style attribute, `State`, parent, siblings) | `dom.Data(n).Style` (`*style.Computed`), clears `DirtyStyle`/`DirtyTree`/`DirtyState`, sets `DirtyLayout` only for changes layout reads, and leaves `DirtyDescendant` only on paths to a node that needs layout | `css.Compute(root *dom.Node, sheets []*css.Sheet)`; `css.Default` is the user-agent sheet, the same text export writes into every page |
| layout (dev-1) | `dom.Data(n).Style`, text through `box.Fonts` | a `*box.Tree` (root box, `Of[node]`), clears `DirtyLayout`/`DirtyDescendant` | `layout.Layout(root *dom.Node, viewport geom.Vec2, fonts box.Fonts) *box.Tree` |
| paint (dev-3) | `*box.Tree`, each box's `Style` | a `paint.Surface` (`*twod.Canvas` satisfies it) | `paint.Paint(s paint.Surface, t *box.Tree)` |
| root (lead) | all | `Document`; points `dom.Data(n).Placed` at `tree.Of[n]` after a layout, and `Node.Box()` asks it for its `Rect()`; a removed node's `Box()` is zero, its descendants keep their last box until dropped | `doc.Layout(size)` runs css then layout |

- `internal/dom`: the node tree. Games use it through `ui.Node` (an alias). Pipeline data is behind `dom.Data(n)`, which games can't import. `Pipeline.Canvas` parks a canvas element's machine, made by `ui.Canvas` with the game's drawing, until the Document's newMachine adopts it, so dom stays free of twod.
- `internal/style`: `Computed`, every value computed. em, rem, var() and keywords are resolved. A `Length` is `Px + Percent%` (calc() of px and % included), or auto, min/max/fit-content, fr or none. `Initial()` is CSS's initial values, with border-box.
- `internal/box`: the `Box` tree. Positions are relative to the parent's border box, before scrolling, as in Taffy. Each box has resolved margin, border and padding edges, scrollable `Content` and `Scroll`, and text `Lines` of fragments. `Rect()` is the absolute border box that Chrome's `getBoundingClientRect` is compared with.
- `box.Fonts` gives `Metrics` (ascent, descent, line gap; `normal` line height is their sum) and `Advance`. Line breaking and wrapping belong to layout. Tests use an Ahem implementation.
- Fonts: `font-family` names families, never files. "Go" and "Go Mono" are built in (weights and italics pick Go Bold/Italic), sans-serif maps to Go and monospace to Go Mono, and other families come from `@font-face { font-family; src: url(file.ttf relative to the sheet); font-weight; font-style }`.
- The Chrome harness is `internal/chrome` (build tag `chrome`). `chrome.Match(t, doc, size)` exports the document, lays it out in headless Chrome and in ui, and fails on any element whose edges are more than 0.5 pt from Chrome's. `chrome.Boxes(page, size)` gives Chrome's rectangles alone. Run it with `go test -tags chrome ./ui/...`.
- Anonymous boxes carry `Initial()` with their parent's Text as Style, so paint never repaints the parent's background or border.
- `display: none` elements get a zero box outside the tree, so `Node.Box()` is all zeros, as in Chrome.
- Layout doesn't round: boxes are fractional, as Chrome's are, and paint may snap edges.
- A `Length` with a percentage has `IsPercent` set, 0% included (0% and 0px differ for flex-basis and grid tracks in indefinite containers).
- Dirty flags: `SetState` marks `DirtyStyle|DirtyState`; id and class changes `DirtyStyle|DirtyTree`; other attributes, `Append` and `Remove` add `DirtyLayout`; text changes `DirtyLayout`. Every mark sets `DirtyDescendant` up the tree. After css, `DirtyDescendant` means something below needs layout: a change only paint shows (colours, backgrounds, borders' looks, shadows, opacity, transforms, outline, cursor) leaves layout clean, and paint reads it through `Shown`.
- `Box.Escapes`: layout sets it on each absolutely or fixed positioned box and on every box above it up to its containing block, whose overflow doesn't hold what it draws. Paint and HitTest walk only the rows a scrollport reaches in a long block-ordered list (`reachable`) and fall back to every row when one has it, so out-of-flow boxes under skipped rows still draw and take the pointer.
- Scroll offsets live in `dom.Data(n).Scroll` across layouts. Layout clamps them to the scrollable overflow and copies them to `Box.Scroll`, which paint reads.
- Retained tree (`layout.Retain`): an element whose subtree is unchanged keeps its node and box; an unchanged element on the path to a change, a table's rows and row groups included, keeps its node and its `*box.Box` too, filled again in place. A box pointer is stable across layouts until its element's own style or children change, so paint and lazy rects may hold it. `Tree.Of` is one map updated in place across retained layouts, valid for the latest layout only; `Tree.Dropped` lists the nodes that layout took out of it (the root clears their `Placed`). A table row keeps its cells' widths and its height while it is kept, so a one-cell edit measures that row alone.
- Replay: a Document replays its last frame when nothing changed, its live parts (a canvas, a caret) drawn apart on top unless found covered. Live parts found covered while kept apart are drawn on top once and the frame isn't recorded, so the next paint has them in their place.
- Classes root builds itself (shortcode suggestions: `ember-suggestion`, `ember-suggestion-emoji`, `ember-suggestion-name`) take the `ember-` prefix, apart from a game's classes and kit's `kit-`, and keep it through the ui → ui rename.
