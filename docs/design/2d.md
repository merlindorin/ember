# 2D as entities

Status: approved and built (`ember/twod`). A design record: the guide documents the API as it is.

2D has the shape the UI has: ready-made entities built with options, added to the World, changed with setters, and drawn in the window they are a child of. They need no node tree, and they save and load as scene nodes. The UI is built on 2D: a ui element is a 2D entity on a fixed layer above the 2D world (decision 0017).

This page describes `ember/twod` as built.

## Package

`ember/twod` holds the 2D entities, their draw order and cameras, and the canvas they and the UI draw on (fonts, text, shapes, images, nine-patches). It is pure Go. It replaced `node/node2d`, `node/canvas` and `ui/paint`.

## Entities

Every 2D entity embeds an `Item`, made of four parts:
- `*world.BasicEntity` and `node.Node`;
- a `Placement`: position, rotation and scale, with `SetPosition`, `Translate`, `SetRotation`, `SetScale` (not `Move`, a name games give their own components' fields, which would hide it). What FixedUpdate moves is drawn between where the last two fixed steps left it, by the clock's Alpha (decision 0002), and cameras follow that drawn position; what Update moves is drawn where it is; `Snap()` skips the blend after a teleport;
- a `Look`: z, tint, visibility and y-sort, with `SetZ`, `SetTint`, `SetVisible`, `SetSortByY`.

| Entity | Constructor | Its own options | Setters and getters |
|---|---|---|---|
| Sprite | `NewSprite(tex, …SpriteOption)` | `Region(r)`, `Still(frame)`, `Size(w, h)`, `Pivot(x, y)`, `Flip(x, y)`, `Animate(anims)`, `Playing(name)`, `Speed(s)` | `SetTexture`, `SetRegion`, `SetStill`, `SetSize`, `SetFrame`, `SetFlip`, `Play`, `Pause`, `Stop`, `Playing()` |
| Line | `NewLine(points, …LineOption)` | `Width(w)`, `Closed()`, `Joints(Miter\|Bevel\|RoundJoint)`, `Caps(start, end)` with `Flat`, `Square`, `RoundCap`, `Color(c)` | `SetPoints`, `SetWidth`, `SetColor` |
| Polygon | `NewPolygon(points, …PolygonOption)` | `Color(c)`; concave shapes are triangulated | `SetPoints`, `SetColor` |
| Text | `NewText(text, …TextOption)` | `Typeface(face)`, `FontSize(points)`, `Wrap(width)`, `Color(c)` | `SetText`, `SetColor`, `Lines`, `Measure` |
| NinePatch | `NewNinePatch(tex, left, top, right, bottom, …NinePatchOption)` | `Size(w, h)` | `SetSize` |
| Layer | `NewLayer(n, …LayerOption)` | `Fixed()`, `Anchor(x, y)`, `Parallax(f)` | `Number`, `Fixed`, `SetAnchor` |
| Camera | `NewCamera(…CameraOption)` | `In(win)`, `Zoom(z)`, `Follow(e)`, `Smoothing(speed)`, `Bounds(r)`, `SnapToPixels()`, `Priority(n)`, `ViewSize(w, h)`, `Layers(l…)`, `Offset(x, y)` | `SetZoom`, `SetFollow`, `SetViewSize`, `SetLayers`, `SetOffset`, `Center` |

- **Shared options:** `At(x, y)`, `Rotate(radians)`, `Scale(x, y)`, `Z(n)`, `Tint(c)`, `Hidden()`, `SortByY()` and `Overlay()` are `Option`s and work on every entity.
- **Typed options:** each kind's own options have their own type, so `Region` on a line or `Width` on a sprite does not compile. `Color` is a `ColorOption`, taken by lines, polygons and texts.
- **Pivot:** `At` places the sprite's pivot, its centre by default, so `Pivot(0, 0)` places its top-left corner.
- **A game's own entity** embeds `twod.Base()` and goes through `twod.Build(e, name, …Option)`.

## Drawing

- **One signature:** an entity draws in `Draw(c *twod.Canvas)`, in its own space: the system has already set the transform and tint. `c.Size()` is its size when it has one, such as a ui element's.
- **Automation:** an entity that implements `Expose() (role string, value any)` is recorded under its name, scoped by the names of the nodes above it.
- **Packages built on twod** set more up through `BeginDraw(c) (end func())`. ui uses it for an element's size and its parents' clips.
- **The canvas** has shapes (rects, rounded rects, circles, rings, orbs, borders, lines, triangles), text (`Text`, `Measure`, `BitmapText`), images and nine-patches, clips, and the record hooks (`Record`, `Expose`, `Push`/`Pop`). It also has the input of the window it draws in: `Mouse` and `Hovered` work through the inverse of the current transform, so a moved, turned or scaled element takes clicks where it shows; `Interact`, `Input` and `Focus` complete them. It has no widgets: ui has them.

## Text, fallbacks and emoji

A game's chat, names and item labels hold emoji, so text works in grapheme clusters and a face can fall back on others.

- **Fallback faces:**
  - `twod.LoadFace(fsys, "Pixel.ttf", twod.Fallback(emoji, symbols))` or `NewFace(ttf, Fallback(…))` makes a face that draws each character with the first face that has it. Engine faces take fallbacks through `face.With(Fallback(…))`, which returns a new face.
  - Texts, ui labels and inputs, and themes (`DefaultTypeface`) all draw through faces, so they all get the fallbacks.
  - `Fallbacks()` reads them back.
  - Bitmap fonts have no fallbacks: a bitmap font is one picture.
- **Glyphs on demand:** a font at a size used to rasterize ASCII and a fixed list of accented letters up front, drawing anything else as `?`. It now adds any other character to its atlas the first time it's drawn, growing the atlas when it fills, so any character a face or its fallbacks hold shows.
- **Grapheme clusters:** text is measured, wrapped and drawn by extended grapheme clusters (UAX #29, through `github.com/rivo/uniseg`, MIT, used only inside twod and ui).
  - A ZWJ family (👨‍👩‍👧), a skin tone (👍🏽), a flag (🇫🇷), a keycap (1️⃣) or a letter with combining accents is one unit.
  - A text input's caret moves, and its backspace deletes, by cluster.
- **Monochrome emoji:** an emoji TrueType font, such as Google's Noto Emoji (OFL), is a fallback like any other and is tinted like text. x/image has no text shaping, so a cluster the font only draws through ligatures shows as its first character: a family as 👨, a flag as its first letter.
- **Colour emoji:** x/image reads no colour tables, so colour emoji are pictures.
  - `twod.LoadEmoji(fsys, dir)` reads a directory of PNGs named by their codepoints, Twemoji's `1f468-200d-1f469.png` or Noto's `emoji_u1f468_200d_1f469.png`. FE0F is ignored on both sides, as Twemoji names its files.
  - `twod.Emoji(set)` is a face option. A cluster the set has is drawn as its picture, inline at the font size and untinted, and its full ZWJ sequence and flags show.
- **Shortcodes:** Slack and GitHub's names.
  - `twod.Shortcodes(s)` replaces every known `:name:` (`:fire:`, `:+1:`, aliases, `:wave::skin-tone-3:`) and leaves unknown ones as written.
  - `twod.ExpandShortcodes()` does it when a text draws.
  - `ui.Shortcodes()` on a text input replaces a name as its closing colon is typed, as one cluster. While a `:na…` is typed, a list of up to six matches opens under the caret, or above it at the window's foot: shortest names first, only those the input's face draws whole (`face.Draws`). It is chosen with the arrows or the pad, inserted with Tab, Enter or south, and closed with Escape or east.
  - The table is GitHub's gemoji v4.1.0 (MIT), generated into `internal/emojinames` by its `go:generate`.
- **Budget:** the engine ships no emoji. The example carries about 100 Twemoji pictures (CC-BY 4.0) and a Noto Emoji subset of the same characters, credited in its CREDITS.md. A game loads a full set from its own files.
- **Alternatives:**
  - Our own segmentation for emoji alone: fewer bytes, but wrong for Hangul and combining marks.
  - Rendering colour tables (COLR/CBDT): x/image can't, and it would mean a font renderer of our own.

## Textures and animations

- **Textures:** `NewTexture(img, …)` wraps an `image.Image`, and `LoadTexture(fsys, name, …)` decodes a PNG from any `fs.FS`, such as an `embed.FS`. `Pixelated()` keeps pixels sharp when scaled.
- **Units:** one texture pixel is one point at `Scale(1, 1)`, so a 16-pixel crate shows 96 points wide at `Scale(6, 6)`.
- **Regions and sheets:** regions are rectangles in texture pixels. `Strip` is the one way to cut a sheet, left to right then top to bottom; a still sprite shows one of its frames with `Still(frame)`.
- **Animations** are data:
  - `NewAnimations().Add(name, fps, frames, Loop()|PingPong()|Once())` builds them, Once by default;
  - a `twod.Frame` is a texture and a region;
  - `Strip(tex, Cell(w, h))` cuts a sheet into frames of w×h pixels.
- **Playing:** `Animate(anims)` gives a sprite clips; `Play` plays one. The end of a clip played `Once` emits `twod.Finished`, and a loop emits `twod.Looped`. Both are World events, read like `ui.Clicked`.

## Draw order

- **Layers** draw in number order. A `Fixed()` layer ignores the camera, for a HUD, and `Parallax(0.5)` moves at half the camera's speed.
- **Resizing** (decision 0021): by default a bigger window shows more world at the same scale. `ViewSize(w, h)` keeps at least that much world in view and scales to fit, 0 freeing an axis, and a `Resolution` camera scales by whole factors. A fixed layer's `Anchor(1, 1)` puts its origin at the window's bottom-right corner, so a HUD keeps its edge.
- **What a camera draws** (decision 0022): every layer, or only its `Layers(…)` and what is in them, such as a minimap camera drawing markers the main view leaves out; a window's fixed layers and UI draw whatever its camera filters.
- **Behind and above:** layers below 0 draw behind the 3D scene. The UI draws on `OverlayLayer`, above every other.
- **Z** orders siblings within a layer and adds to the parent's.
- **`SortByY()`** on a parent draws its children by their y, for top-down depth.
- **Tint** multiplies an entity and its children, so a layer's `Tint` tints everything in it.

## Without a tree

`twod.System` plays animations, moves cameras and draws each window's 2D children, else the primary window's. It follows World and node links, so the same entities loaded from a `.glb` scene draw the same way. It runs late in Update, after the ui system has laid elements out.

## Cameras

- **One per window:** `NewCamera(In(win))`. Without `In`, it is the primary window's, and the highest `Priority` wins.
- **No camera:** the origin is the window's top-left corner and one unit is one point.
- **With a camera,** the view centres on its position or on the entity it `Follow`s. `Zoom`, `Smoothing` and `Bounds` shape it, and `SnapToPixels()` rounds it for pixel art.
- **Screen positions:** `twod.ToScreen(w, e)` is where an entity showed last frame. `ui.Follow` uses it to pin an element to a 2D entity.

## UI on twod

- **What each holds:** `twod` is all drawing: shapes, images, nine-patches, text, layers, order and transforms. `ui` adds layout, interaction, themes and automation IDs.
- **ui elements are entities:** they embed `twod.Look` but no `Placement`. `Local()` comes from the layout, so `At` and `Anchor` are their only placement.
- **Same contract:** they draw in the same `Draw(c)` as 2D entities, on the overlay layer.

## Decided

1. **The package is `ember/twod`.**
2. **Private state:** scene properties live on unexported fields with setters, in twod and ui alike.
3. **No self-only tint:** a tint applies to an entity and its children.
4. **Draw order:** the 3D scene, then 2D, then the UI. Negative 2D layers draw behind the 3D scene.
5. **Units:** one 2D unit is one point at zoom 1.
6. **One custom-draw signature,** `Draw(c *twod.Canvas)`, with an optional `Expose`.
7. **Typed options:** shared options for every entity, and per-kind option types for the rest.
8. **One sprite type,** which also plays animations.

## API rules, as built

The guide's read-through found nine places where the 2D API said the same thing several ways. The rules below settle them; the code follows them.

1. **At places the pivot.**
   - Sized entities (sprites, nine-patches, texts) are pivoted at their centre unless `Pivot` says otherwise.
   - In ui, the pivot is the `Anchor`: `Anchor(Center)` puts the element's centre on its parent's centre, offset by `At`.
   - A tile map's pivot is the top-left corner of its first cell; a line's or a polygon's is the origin of its points.
2. **One verb for children:** `Add(children…)` on windows, on every twod entity and on ui containers. It takes any entity (a collide body too) and returns the parent for chaining. `AppendChild` is the low-level call of `world`.
3. **Size is a box in points:**
   - `Size(w, h)` is ui's layout box, a nine-patch's box and the box a sprite fits its picture to (`Scale` still multiplies it);
   - `FontSize` is a text's font size, `CellSize` a tile map's cell size;
   - `Measure()` gives a text's or a bitmap text's measured size.
4. **Color draws, Tint multiplies:** `Color` is what a text, line or polygon draws with; `Tint` multiplies an entity and all its children.
5. **Cameras across packages** (twod, `camera`, `render.Camera`) wait for the 3D API pass.
6. **Loaders:** `LoadX(fsys, name, opts…)` reads a file, `NewX(data, opts…)` takes data in memory:
   - `LoadTexture`/`NewTexture`;
   - `LoadFace`/`NewFace`;
   - `LoadBitmapFont`/`NewBitmapFont` with `Cell(w, h)` and `Charset(s)`;
   - `LoadTiled`.
7. **Effects are values with options:** `render.NewEffect(shader, Name, Screen)`, with private state and typed setters (`SetEnabled`, `SetFloat`, `SetVec2/3/4`, `SetColor` and the slice setters for uniform arrays, read back with `Uniform`). A layer takes one with `twod.WithEffect(e)`.
8. **Strip cuts sheets:** a still frame is `Still(frame)`, set with `SetStill(frame)`; `Frame`/`SetFrame` are the playing clip's frame index.
9. **Resolution units:** under a camera with `Resolution`, one world unit is one pixel of that resolution; fixed layers and the UI stay in window points.
