# ember

ember is a Go game engine for online open-world games, built on its own ECS (`world`). Module `github.com/merlindorin/ember`; this folder is the module root. It never imports a game built on it (guarded by a test).

Engine decisions live in `docs/99-decisions/`, one short file each from its `TEMPLATE.md` (context, decision, alternatives, consequences), and the guide publishes them. Read its README before changing behaviour. Only real engine choices with alternatives belong there, recorded once they settle; add the file and its index row in the same commit, and supersede instead of rewriting.

## Architecture

- Entities are structs embedding `*world.BasicEntity` plus components, and each component has a `GetX()` getter. A system embeds `world.Group[SomeInterface]` and receives matching entities automatically. Phases run in this order: Startup (once), PreUpdate, FixedUpdate, Update, PostUpdate.
- Models: `gltf.Load`/`LoadFS` then `model.Spawn(world, transform)`. Skinning is CPU-side in `anim` (`AnimatorSystem` then `SkinSystem` in Update), installed by `ember.New`. Props go in joints with `Instance.Attach` (an `anim.Socket`); procedural moves use `Animator.Constraints` (`TwoBoneIK`, `Aim`, `Turn`, `Shift`, `Overlay`) in model space. Clips loop over [Clip.Start, Duration] (exports often start at 1/30 s). Locomotion clips with travel need `Animator.RootMotion` (RootJoint = hips) and moving the entity by `Motion()`, or they snap back at each loop. Material textures are `render.Texture` (plain image data the GPU caches by pointer and version).
- Visual styles are game code: compose them from a camera's `Post` (`cam.Post = render.NewPost()`: scene resolution, MSAA, WGSL `render.NewEffect` chain, upscale filter) rather than adding style options to the engine.
- The look of the world is an entity: add a `render.NewEnvironment(opts…)` (the first one lights the scene). Gizmos and billboards are entities too (`render.NewGizmos()`, `render.NewBillboards()`), cleared each frame. A camera's resolved view is `cam.View()`; each window presents its highest-Priority camera.
- Scenes and nodes (`docs/design/scenes.md`): a scene is a self-contained .glb whose nodes carry `EMBER_node` (class as package.Type, groups, process_mode, Go behaviour, properties are `node:"prop"` fields named in snake_case, exported or not (new entities keep theirs unexported with setters), enums as words) and whose root carries `EMBER_scene` (connections, instances by scene ID, inherits). `node` holds the tree, lifecycle, signals, scene codec, `node.Empty` and `node.Timer`; `node/node3d` holds the 3D types and Instantiate/Pack, `twod` the 2D entities (scene nodes `twod.X`), and `twod` the shared layers and draw order (2D and UI both draw through `twod`).Canvas`). Scenes reference each other by ID, never by file path. No other engine's names are a reference. `SceneService` (ember.scene.v1) inspects and snapshots a running tree on the automation server.
- Rendering is **not** a system. The `world.World` calls its presenters (`AddPresenter`) after simulating, and they observe entities through `World.AddView`. Systems take a `world.Frame` (DT, Elapsed, FixedFrame, Time, World, Quit); the World has `Time()` (scale, pause), `Stats()` and `Timings()`. `ember.New` returns the World. The engine exposes no resources (decision 0015): its services are values the game builds with options and passes in or adds as entities; `world.Resource` is for game values only (guarded by `resources_test.go`): the game passes `ember.Automation`, serves its scene tree with `automation.Scenes(tree)`, and holds `spatial.NewIndex(cell)` with `spatial.NewIndexer(idx, spatial.Fixed())`; engine packages share state through `internal/slot`. Every `world.Group` field of a system (named or embedded, exported or not) is filled, so one system can collect several kinds. A component field named like a method hides it and silently drops the entity from groups; `w.Explain(e)` says why. Groups take an entity when it is added; after a change that makes it match or unmatch, `world.Regroup(e)` offers it again (applied at the frame's flush). Light options on a live entity apply the next frame (setters `light.SetOccluder`, `SetSilhouette`, `RemoveOccluder`, `SetHeight`, `SetEmissive`). Engine getters are specific (`GetSceneNode`, `GetDrawLook`, `GetCollider`, `GetSoundEmitter`) so games keep the short names. Appending a child to an entity already in a World adds it and its subtree to that World; removing a parent removes its children. Removing an entity also takes it out of its node tree (`world.TreeMember`).
- 2D: `twod` holds sprites (which also play animations), lines, polygons, text, nine-patches, layers and 2D cameras, and the canvas everything 2D and UI draws on: entities built with options, shown in the window they're a child of, ordered by layer, z and `SortByY`, with bitmap texts (`NewBitmapText`, `LoadBitmapFont`) and layer clipping (`ClipTo`); `At` places the pivot of sized entities (centred by default; `Pivot(0, 0)` for the top-left). `Add(children…)` on windows, twod entities and ui containers returns the parent; `Size` is a box in points (`FontSize`, `CellSize`, `Measure`); sheets are cut by `Strip`, a still frame is `Still`; loaders are `LoadX(fsys, name, opts…)`/`NewX(data, opts…)` (design: `docs/design/2d.md`). Faces take `twod.Fallback(faces…)` and `twod.Emoji(set)` (NewFace/LoadFace options, or `face.With(…)` for engine faces); glyphs rasterize on demand; text works by grapheme cluster (uniseg, internal); `twod.LoadEmoji(fsys, dir)` reads Twemoji/Noto PNG names and draws them inline, untinted. The engine ships no emoji. Shortcodes: `twod.Shortcodes(s)` and `twod.ExpandShortcodes()` (gemoji names, aliases, `:skin-tone-N:`, table generated into internal/emojinames); `face.Draws(text)` reports whether a face draws text whole. What FixedUpdate moves is drawn interpolated between fixed steps (Alpha); cameras follow the drawn position; `Snap()` after a teleport. Sample input in PreUpdate so FixedUpdate uses it the same frame. A ui Document is a twod entity: twod draws, ui adds layout, interaction, CSS and automation IDs.
- 2D cameras and resizing (decisions 0021, 0022): by default a bigger window shows more world at the same scale; `twod.ViewSize(w, h)` keeps at least w×h in view and scales to fit (0 frees an axis); `twod.Anchor(x, y)` puts a fixed layer's origin at that fraction of the window; `twod.Layers(layers…)` makes a camera draw only those layers (and nested ones), while fixed layers and the UI always draw.
- 2D passes: a twod camera with `Resolution(w, h)` draws its world into an offscreen pass (`twod.PassesFor`) that the window shows scaled and letterboxed; the GPU draws a window's passes before the window. Fixed layers and the UI stay at the window's resolution. The scaled world composites as one picture where its first layer stands. A layer with a Blend other than Alpha, `AsMask` or `MaskedBy` draws as a pass too, shown as one picture; Blend applies to the entity itself, never its children. `twod.Filter` is `render.Filter`. `twod.NewRenderTexture` + `twod.Into(tex)` make a camera draw into a texture sprites show; it is a value, never a GPU handle. `twod.WithEffect(render.NewEffect(shader, …))` runs a layer through WGSL (uniforms via `SetFloat`/`SetVec4s`…) (post header, premultiplied uColor, no depth); a shader that fails to compile reports it through `Effect.Err()`.
- Rendering is WebGPU only (decision 0041, `docs/design/webgpu.md`; OpenGL removed in 3868f136): ember's own cgo binding to wgpu-native v29 is `internal/wgpu` (headers vendored, the library opened at run time, so builds never need it). Running needs the library once: `task wgpu` fetches it into the gitignored `internal/wgpu/lib/<os>-<arch>/`, found via `EMBER_WGPU_LIB`, beside the executable, or there; builds ship it beside the game. Shaders are WGSL, and so are effects (`render.NewEffect(wgsl)`, `fn effect(vUV: vec2f) -> vec4f`, vUV 0–1 from the top-left everywhere). `task golden` (`go test -tags gpu ./gpu -run Golden`) checks 13 scenes against the golden pictures in `gpu/testdata/golden` (`-update` rewrites them); plain `go test ./...` needs no GPU.
- The renderer's 2D internals (draw lists, batches, passes, glyph atlases) are `internal/draw`: twod installs a `draw.Source`, and gpu reads it. Games draw only through `twod.Canvas` (shapes, images, `Text`/`Measure` with text options).
- Recent engine rules: events wait until a fixed step has begun after them while the World has FixedUpdate systems, so every phase's readers see each event once (decision 0023); `Reader.Any(w)`/`Count(w)` consume like `Read`; `Children()`/`Descendents()` return the appended entities themselves (type-assert them); a finished `Once()` tween emits `ease.TweenFinished`, then leaves its parent and the World; `Time().RealElapsed` is unscaled, unpaused time for menus; `twod.Offset(x, y)` nudges a camera after Follow (shake is game code).
- ui for game screens: a screen is a `ui.Document` (`kit.Theme()`, `Stylesheet`/`CSS`, `Emoji`, `WithTranslator`, `Zoom`) added to its window; `kit.Wrap()`/`kit.Truncate()` on labels; a card is a `ui.Button` holding blocks; `kit.Tooltip(tip)` flips beside its element on hover or focus; `ui.Follow(entity, offset)` pins an element over a 2D entity; Tab moves focus only while something has it, otherwise the game gets it; `win.Input().LastDevice()` (Keyboard/Mouse/Gamepad/TouchDevice) picks button hints (`kit.Hint`).
- Particles are a twod entity: `twod.NewParticles(tex, Rate, Burst, OneShot, Lifetime, Velocity, Direction, Gravity, Drag, ColorOverLife, SizeOverLife, Spin, LocalSpace, MaxParticles, Seed…)`, simulated on the CPU in the twod system; a one-shot emits `twod.ParticlesFinished`.
- Easing and tweens are `ease` (pure): `ease.InOutQuad`… are `ease.Func`s, and `ease.NewTween(seconds, apply, Easing, Delay, Loop|PingPong|Once)` is an entity, added as a child of what it moves, that `ember.New`'s ease system advances each frame (emits `ease.TweenFinished`). Curves are geom functions generic over Vec2/Vec3: `QuadBezier`, `CubicBezier`, `CatmullRom`, `ClosedCatmullRom`.
- Tile maps: `twod.NewTileset(tex, twod.Cell(w, h), Solid, Tall, TileAnimation…)` and `twod.NewTileMap(tileset, Cells|CSV|ASCII, CellSize, TallIn…)` (a map's position is the top-left of cell 0,0, the one exception to centred pivots); `twod.LoadTiled` reads Tiled JSON. Collision (`collide`, pure Go): the game holds `collide.NewSpace()` and adds `collide.NewTracker(space)`; bodies are added to their owner (`owner.Add(collide.NewBody(collide.Box(w, h), collide.Group(n), collide.CollidesWith(…)))`), and `collide.Grid(size)` sets the space's cell; `space.Move(owner, delta)` stops and slides; tile maps are solids (`space.AddSolid(map)`). Pathfinding is `nav` (pure): `m := nav.New(tileMap)`, `m.Find(from, to)` / `m.Route(from, to)` with `route.Toward(at, reach)`, which re-plans when the grid's `Version` changes (TileMap.Set) or its way is blocked; diagonals never cut corners; `m.Clear(a, b)` is the line-of-sight test. A horde steers by `nav.NewFlowField(nil, nav.Around(infiniteMap.AreaAround, 128, 128))`: `SetTarget(hero)` each frame (rebuilds only on a new goal cell, a grid Version change or a re-cut; about 0.9 ms for 128×128), `Toward(at) (dir, ok)` in constant time, falling back to straight when not ok (decision 0024). `twod.NewInfiniteMap(tileset, ChunkSize, Generator(func(cx, cy, cells)), KeepChunks, CellSize, TallIn…)` is an endless map of chunks generated on demand (LRU past KeepChunks; edited chunks kept), a collide.Solid, with `Area(x, y, cols, rows)` as a nav.Grid. The collide tracker runs late in FixedUpdate, so `collide.BodyEntered`/`BodyLeft` fire per fixed step in a stable order.
- Option rules (decisions 0018, 0019): every option has a getter of the same name, setters exist where runtime change is meant and take the option's arguments (`Hidden()`/`SetHidden`, `Rotation`/`SetRotation`); options have no `With` prefix unless the bare name clashes with a type (`twod.WithEffect`, `audio.WithBus`); `twod.Cell(w, h)` is the one grid (Strip, tilesets, bitmap fonts); clips and tweens repeat with `Loop()`/`PingPong()`/`Once()`; events are `<Subject><Past>` (`AnimationFinished`, `ParticlesFinished`, `ease.TweenFinished`). Faces (`twod.Regular()`…) and easings are functions; `Camera.WorldToScreen` pairs with `ScreenToWorld`. Example windows use `platform.FixedSize()` unless their content follows the window.
- Names (decision 0044): lights cast shadows unless `light.Shadows(false)` (every kind; no XRay); `light.OccludersFrom(space)`; occluder groups everywhere (`light.Occluder(groups…)`, `BlockedBy`, `twod.OccluderGroup`, tile property `occluder_group`); `twod.CastShadow(on, ids…)`; `Size` is the one penumbra option; per-window getters are XOf (`light.DebugOf`, `AmbientOf`); text drop shadows are `twod.TextShadow`; tiled pictures are smooth unless `twod.Pixelated()`; With only where the bare name clashes with a type (`WithTheme`, `WithEffect`, `audio.WithBus`, net's `WithCodec/WithListener/WithEndpoint`).
- Options are typed per kind of entity or element: shared `twod.Option` work on all, kind-specific ones (`twod.SpriteOption`…) only where they apply, so a wrong option fails to compile. ui elements take `ui.Arg`s (attributes, classes, styles, callbacks), and kit's options are Args.
- Sound (decision 0020): `audio.NewMixer(...)` is an entity; `audio.Load`/`audio.Open` read WAV or Ogg once `audio/wav` or `audio/vorbis` is imported; emitters are `*audio.Emitter` components heard from the first `audio.Listener`. `audio` is pure Go: without a device a mixer mixes into a null output at the World's pace, and tests check `audio.NewRecorder(mixer)`. The device (`internal/audiodevice`, oto) opens only in the desktop runner, never under EMBER_HIDDEN, and must not be imported from server code. Effects: `audio.NewReverb`/`NewLowPass`/`NewHighPass`/`NewEcho` with typed options (RoomSize, Damping, Cutoff, Resonance, Delay, Feedback, Wet), chained with `audio.Effects(...)` on a voice/emitter or a bus (`WithBus(name, vol, audio.Effects(...))`, `Bus.SetEffects`); setters glide over 10 ms, so tween freely; one effect value belongs to one bus or voice.
- Networking: the game makes and keeps `net.NewServer(opts…)` / `net.NewClient(conn, opts…)` and adds them as plugins; neither is a resource.
- Keep the pure packages free of cgo: `render`, `scene`, `net`, `world`, `ui`, `twod`, `collide`, `nav`, `ease`, `audio`, `anim` and `gltf` must not import `gpu`, `internal/wgpu`, `platform/desktop` or GLFW, so servers stay pure Go.
- Cameras: `camera.NewOrbit`, `camera.NewFollow(target, …)` and `camera.NewFly(…)` are ready-made camera entities that read their own window's input (`camera.In(win)`); a game's own camera embeds `OrbitBase`/`FollowBase`/`FlyBase` and goes through `BuildOrbit`/`BuildFollow`/`BuildFly`. Options are typed per controller. `ember.New` installs the camera controllers.
- `scene.TransformSystem` runs at PostUpdate priority 1000, camera controllers at 500, and `render.ViewSystem` at -1000.
- Examples must not reference raylib (see CLAUDE.local.md).
- UI (decisions 0049, 0057, 0059, 0060): HTML elements built from Go (`ui.Div`, `Button`, `Input`…, or kit's `kit.Button`, `kit.Label`, `kit.Panel`, `kit.Row`…) with Args, appended to a Document's `Body()`; the Document is an entity added to a window. Styles are a CSS subset (flex, grid, the cascade) checked against headless Chrome; kit's classes are `kit-…`, classes the engine builds `ember-…`. Interaction is callbacks on the element (`ui.OnClick`, `OnInput`, `OnChange`, `OnSubmit`, `OnBack`…): screens, tools and examples use them, so the reaction reads beside the element; the World events (`ui.Clicked`, `Edited`, `Changed`, `Submitted`, `BackPressed`) are for code that isn't the element's builder (a system elsewhere, tests). Back and key callbacks bubble from the focused element to its ancestors (`e.StopPropagation()`), so a screen puts one `OnBack` on its root; the rest stay on their element. Custom drawing is `ui.Canvas(func(c *twod.Canvas))`. Fonts come from `@font-face` in a `Stylesheet`; `align.Check(doc)` (ui/align) and `doc.Warnings()` are the tests every screen runs (design: `docs/design/ui.md`, guide `docs/05-ui`).
- Multi-window: windows are `*platform.Window` entities from `platform.NewWindow(opts…)` (title, size, background…); the first added is the primary, and `ember.New` opens a default one only when none is added. Input is `win.Input()`: `Down`/`Pressed`/`Released(button)` for keys and mouse buttons alike, `Direction`/`Axis`, `Mouse()` in window points (`cam.ScreenToWorld` for the world), `Wheel()`, `Text()`, `Dropped()`, read-only `PointerCaptured()`/`KeyboardCaptured()`; a Key is a physical position. Games read intent with `input.NewActions(input.Bind(Act, buttons…))`. `SetKey`/`SetMouse`/`AddWheel`… simulate input in tests and captures, and show from the next frame: the World begins each window's input frame itself, so a test sets input and calls RunFrames; the backend side is `internal/inputfeed`. Gamepads are on the primary window's input: `GamepadButton`s named by position (`GamepadSouth`…; triggers and stick directions such as `GamepadLeftStickLeft` are analog, read with `Value`) work in `Down`/`Pressed` and `input.Bind`; `in.Stick(input.LeftStick)`, `SetDeadzone`; `in.Gamepads()`/`in.Gamepad(id)` per player (the action map reads an `input.Reader`: the input or one pad); `input.GamepadConnected`/`GamepadDisconnected` are World events; `ConnectGamepad`/`SetGamepadButton`/`SetGamepadStick`/`SetGamepadTrigger` simulate them. No rumble (GLFW 3.3). Touch: `in.Touches()` (`Trackpad` touches are 0–1 on the pad, never window points; `Touchscreen` in points), `Pinch()`/`Rotation()`/`Pan()`/`Swipe()`, `input.TouchStarted`/`TouchMoved`/`TouchEnded` World events; macOS only for now (platform/desktop/touch_darwin.go); `AddTouch`/`AddPinch`… and `EMBER_CAPTURE_TOUCH` simulate them. Windows also have `SetCursor(platform.CursorText|Hand|Hidden|Arrow)` and `Clipboard()`/`SetClipboard`. Window options also cover resizing and state: `FixedSize()`, `MinSize`/`MaxSize`, `AspectRatio`, `Maximized()`, `Fullscreen()`, `AlwaysOnTop()`, `Icon(images…)`, each with a runtime setter (`SetFullscreen`, `Maximize`…). a camera renders in (and reads the input of) the window it is under, with `render.Camera.Window` / `camera.In(win)` / `twod.In(win)` only for one outside any window; a UI element shows in the window entity it is a child of, and engine packages find the primary and presented windows through `internal/wm`.
- Automation: `automation` serves `ember.automation.v1.Automation` over Connect (gRPC-compatible) with server reflection when `EMBER_AUTOMATION=host:port` is set (`grpcurl -plaintext host:port list`). ui elements record themselves, with IDs that are paths of their names (id, else `data-name`, aria-label, text, label, placeholder; `data-name` and id also scope descendants); acts are `press`, `set`, `type`, `submit`, `select`. Text fields share an editing core (internal/textedit): selection by keys and mouse, word and line moves, clipboard, undo; `kit.ShortcodeField` turns `:name:` into emoji with a suggestion list (`<field>-suggestions`); one focused element per window with Tab order, spatial arrows and pads, Escape/East emitting `ui.BackPressed`; a modal owns its window's input (decision 0053). Expose game intents as `automation.Action`s. Regenerate the proto with `go generate ./automation` (needs buf; protoc-gen-go and protoc-gen-connect-go run as go tools pinned in ember/go.mod). Games make `auto := automation.New(opts…)`, pass it with `ember.Automation(auto)` and call `auto.Define`; engine packages reach it through `internal/slot`. Tests record without serving with `automation.New(automation.Recording())`.
